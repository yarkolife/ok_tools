## Стратегия инвалидации кэша

### Создан модуль инвалидации кэша

Был создан новый файл `dashboard/cache_invalidation.py`, который содержит:

1. **Общую функцию инвалидации** `invalidate_dashboard_cache()` для очистки всех связанных с дашбордом ключей кэша
2. **Селективные функции инвалидации** для конкретных типов данных:
   - `invalidate_license_related_cache()` - для лицензий
   - `invalidate_contribution_related_cache()` - для вкладов
   - `invalidate_project_related_cache()` - для проектов
   - `invalidate_user_related_cache()` - для пользователей

3. **Сигналы Django** для автоматической инвалидации кэша:
   - `post_save` и `post_delete` для моделей License, Contribution, Project, Profile
   - При создании, обновлении или удалении этих моделей автоматически сбрасывается кэш

### Регистрация сигналов

Сигналы зарегистрированы в `dashboard/apps.py` через импорт модуля `dashboard.cache_invalidation`, что обеспечивает их активацию при запуске приложения.

## Технические детали реализации

### Генерация ключей кэша

- Используется хэш-функция от параметров запроса для создания уникальных ключей
- Префиксы ключей соответствуют типу данных (например, `licenses_stats_`, `users_basic_stats_`)
- Для виджета contributions используется префикс `contributions:`

### Время жизни кэша

- **10 минут** для быстро меняющихся данных (quick_stats)
- **15 минут** для данных средней изменчивости (inventory_stats, registration_trend)
- **20 минут** для статистических данных (licenses_stats, basic_stats)
- **25 минут** для относительно стабильных данных (демографическая статистика)
- **30 минут** для наиболее стабильных данных (общая статистика)

### Использование Redis

- Кэширование реализовано через `django.core.cache.cache` с настроенным Redis бэкендом
- Для инвалидации кэша используется pattern matching для удаления ключей по шаблону
- Предусмотрен fallback к `cache.clear()` если redis-redis недоступен
